## Scope, interpretations and remaining qualification

§15.1 explains taxonomy limitations; no universal name-classification algorithm is
inferred. The generic-family sample font lists, weight-mapping examples, HTML-size
guidelines and sample rules are illustrative. They are not mandated bundled assets.
Naming heuristics and keyword-size recommendations remain distinct from compulsory
matching order and relative-weight tables. The system-font example says9-point but
then writes9px; use normative unit conversion, not that inconsistent example.

§15.7's property-specific em/ex rule resolves the broad root-relative wording in
§4.3.2: initial-font fallback supplies the missing parent basis for root font-size;
other root properties use the root computed font size, not an unrelated initial
font size. This is a recorded cross-clause interpretation. Actual ex metrics and
font-relative unit qualification remain with50/57 and their earlier decisions.

Matching remains specified per character; the architecture's shaping-safe cluster
fallback must be qualified against that obligation where a cluster spans fonts,
styles or source elements. HarfRust's bounded suite is not execution of these CSS
matching assertions. Monospace equality, emergency-font licenses, generic mapping,
synthetic small-caps/case behavior, system role snapshots, and all target discovery
remain dependencies. No bundle/OS role is claimed verified by reading CSS.
